# GitHub-помощник в Telegram

Личный бот для репозиториев `kenshiki36-blip`: читает код с GitHub, показывает структуру и файлы, ищет функции, объясняет проект через Grok от xAI, Groq или Google Gemini и даёт ссылки на конкретные строки коммита. Node.js 22+, без внешних npm-пакетов.

В шаблоне настроек выбран **Grok от xAI** (`AI_PROVIDER=xai`). Ключ вводится через `setup-grok.cmd`, после сохранения нужен `restart.cmd`. Запросы идут в xAI Responses API с Bearer-авторизацией. `npm run doctor` проверяет подключение и доступность выбранной модели. Groq и Gemini поддерживаются как отдельные провайдеры.

Оплата Grok API определяется [тарифами xAI](https://docs.x.ai/developers/pricing). Если выбран Gemini, используется `gemini-3.5-flash-lite` с [бесплатной квотой Google](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.5-flash-lite) для проектов Free tier. При ошибке API бот показывает результаты поиска по коду; другие провайдеры автоматически не подключаются.

## Запуск в Windows

1. Установи [Node.js 22 или новее](https://nodejs.org). Проверка: `node --version`.
2. Запусти `start.cmd`. При отсутствии `.env` он создаст файл из `.env.example` и откроет Блокнот.
3. В `.env` нужны `TELEGRAM_BOT_TOKEN` от [BotFather](https://t.me/BotFather) и `ALLOWED_TELEGRAM_IDS`. Свой ID можно узнать, отправив боту `/id`.
4. Для Grok получи ключ в [консоли xAI](https://console.x.ai) и запусти `setup-grok.cmd`. Для Groq используй `setup-groq.cmd`, для Gemini — `setup-gemini.cmd`. Окно настройки принимает ключ скрытым вводом и сохраняет его только в локальный `.env`. Можно заполнить переменные вручную по таблице ниже.
5. Перезапусти `start.cmd` и открой своего бота в Telegram. Для кода этого бота с компьютера отправь `/local`. Для проекта на GitHub — `/repos`, затем `/repo имя`. После индексации задай вопрос.

Ключи нового формата Google начинаются с `AQ.`; точка является частью ключа. Окно настройки сохраняет её и не должно изменять скопированное значение. Ошибка HTTP 400 требует проверки ключа или запроса, а не простого ожидания.

Без ключа выбранного ИИ бот работает в режиме поиска: показывает найденные фрагменты со ссылками, файлы, дерево и коммиты. Для публичных проектов GitHub-токен необязателен. Для приватных нужен fine-grained `GITHUB_TOKEN` с доступом к нужным репозиториям и `Contents: Read-only`.

Остановка — `Ctrl+C`. Для работы компьютер должен оставаться включённым, а процесс Node.js — запущенным. Автозапуск Windows не устанавливается.

После исправления кода или настроек можно запустить `restart.cmd`: он проверяет PID, имя процесса и время записи PID в блокировку, останавливает прежний экземпляр и запускает новую версию. Если процесс не удаётся однозначно сопоставить блокировке, перезапуск прерывается. Используется время записи, поскольку Windows может сохранить старое время создания файла после его пересоздания.

При обычном запуске текущие события и ошибки сохраняются в `data/bot.stdout.log` и `data/bot.stderr.log` с датой и временем. В журнал попадают стадии работы и длительность запроса Gemini; вопросы, ответы и ключи не записываются.

Вместо двойного клика можно использовать терминал:

```powershell
npm start
npm run setup:gemini
npm run doctor
npm test
```

`npm run doctor` проверяет Telegram, GitHub и, если ключ задан, доступность модели Gemini. Эта проверка не отправляет сообщения пользователям и не вызывает генерацию ответа. После изменений `.env` перезапусти бота.

При таймаутах Gemini запусти `check-gemini.cmd` в обычном Windows. Он отдельно проверяет доступ к выбранной модели и короткую генерацию без кода проекта. На чтение модели даётся 15 секунд, на пробный ответ — 20 секунд. Отчёт сохраняется в `data/gemini-check.json`: только этап, длительность, код ошибки и признаки успешного ответа; ключ и исходники в отчёт не попадают. Проверка не останавливает работающего бота и не меняет модель, ключ или тариф.

## Настройки

Для **Groq** (`console.groq.com`, ключ `gsk_…`) запусти `setup-groq.cmd`. Для **Grok от xAI** (`console.x.ai`, ключ `xai-…`) — `setup-grok.cmd`. Оба окна принимают ключ скрытым вводом и сохраняют выбранный `AI_PROVIDER` в `.env`. После сохранения запусти `restart.cmd`. Это разные сервисы с разными ключами и тарифами; тариф Google Free tier к ним не относится.

Поддерживаются `AI_PROVIDER=groq` с `GROQ_API_KEY` и необязательным `GROQ_MODEL`; `AI_PROVIDER=xai` с `XAI_API_KEY` (или `GROK_API_KEY`) и `XAI_MODEL` (или `GROK_MODEL`). Ключ выбранного сервиса отправляется только на его фиксированный API-хост. При ошибке используется локальный поиск; обращения к другому провайдеру автоматически не выполняются. Для проверки выбранного API используй `npm run doctor`.

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота |
| `ALLOWED_TELEGRAM_IDS` | Числовые ID пользователей через запятую; без них доступна только `/id` |
| `GITHUB_OWNER` | Владелец репозиториев, по умолчанию `kenshiki36-blip` |
| `GITHUB_TOKEN` | Необязательный токен GitHub для приватных проектов и большей квоты |
| `AI_PROVIDER` | `xai`, `groq` или `gemini` |
| `XAI_API_KEY`, `XAI_MODEL` | Ключ xAI и модель Grok; также поддерживаются имена `GROK_API_KEY`, `GROK_MODEL` |
| `GROQ_API_KEY`, `GROQ_MODEL` | Ключ и модель Groq |
| `GEMINI_API_KEY` | Ключ Google Gemini; также поддерживается `GOOGLE_API_KEY` |
| `GEMINI_MODEL` | По умолчанию `gemini-3.5-flash-lite` |
| `GEMINI_TIMEOUT_SECONDS` | Ожидание Gemini до перехода к поиску: 5–120 секунд, по умолчанию 45 |
| `MAX_FILES` | Число индексируемых текстовых файлов: 1–500, по умолчанию 100 |

Старые `OPENAI_API_KEY` и `OPENAI_MODEL` больше не используются. Бот обращается к Gemini REST API `generateContent`; ключ передаётся в заголовке `x-goog-api-key`.

## Команды

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Справка и текущий режим ответов |
| `/id` | Узнать свой Telegram ID |
| `/repos` | До 60 последних репозиториев владельца |
| `/repo имя` | Выбрать и прочитать репозиторий; также принимает `owner/repo` или GitHub URL |
| `/local` | Прочитать текущие локальные исходники этого бота |
| `/status` | Выбранный проект, коммит, дата индекса и режим ответов |
| `/tree [папка]` | До 150 путей в дереве |
| `/file путь` | Первые 200 строк файла из индекса, до 14000 символов |
| `/search запрос` | Найти фрагменты по имени функции, пути или теме без запроса к ИИ |
| `/commits` | Пять последних коммитов из текущего снимка |
| `/refresh` | Обновить снимок с GitHub и очистить историю вопросов |
| `/reset` | Очистить историю вопросов |

Примеры вопросов: «Как запустить проект?», «Где точка входа?», «Как устроена авторизация?», «Каких настроек не хватает?». Подсказки команд добавляются в меню Telegram при запуске.

## Индексация и состояние

В режиме GitHub бот получает дерево и файлы одного коммита. В индекс попадают до `MAX_FILES` текстовых файлов размером до 100000 байт каждый. README, настройки сборки и точки входа имеют приоритет. Для публичных репозиториев содержимое загружается через `raw.githubusercontent.com` по SHA коммита: каждый файл не тратит отдельный запрос REST API. Приватные файлы читаются через авторизованный GitHub API; токен не отправляется на raw-хост.

Команда `/local` читает только папку этого приложения. `.env`, `data`, зависимости, служебные каталоги и символические ссылки пропускаются; произвольный путь из Telegram передать нельзя. Локальные данные помечаются отдельным источником и хешем содержимого; ссылки на коммит GitHub для них не создаются. `/refresh` повторно читает текущий выбранный источник. Как и фрагменты GitHub, выбранные фрагменты локального кода передаются Gemini для ответа.


Файлы делятся на фрагменты по строкам. Для вопроса выбираются до девяти фрагментов с общим бюджетом до 42000 символов; русские вопросы о запуске, авторизации, настройках и тестах сопоставляются с распространёнными английскими именами в коде. Это локальный поиск по словам, без embeddings. Без ИИ выводятся до трёх найденных фрагментов. Если совпадений нет, бот прямо сообщает об этом.

Выбор проекта и Telegram offset сохраняются в `data/state.json`, снимки кода — в `data/indexes/`. После перезапуска сохранённый индекс восстанавливается автоматически; история диалога хранится только в памяти. Кэш другого владельца или недопущенного пользователя не загружается. Повреждённый кэш пропускается и может быть заменён командой `/refresh`; повреждённый `state.json` сохраняется, а запуск останавливается с понятной ошибкой.

Данные записываются через временные файлы и переименование. Блокировка `data/bot.lock` не допускает второй экземпляр. Если PID старого процесса больше не существует, старый файл блокировки сохраняется как `bot.lock.stale.*`, после чего запуск продолжается.

## Данные и ограничения

- Бот отвечает только разрешённым Telegram ID в личных чатах и читает проекты только заданного `GITHUB_OWNER`.
- `.env*`, известные секреты, ключи, бинарные файлы, зависимости, сборки и lock-файлы исключаются из индекса. Известные форматы токенов маскируются; автоматическая фильтрация не гарантирует обнаружение любого секрета.
- `.env` и `data/` исключены из Git. Кэш содержит прочитанный код, поэтому обращайся с ним как с исходниками.
- В Gemini передаются вопрос, до шести сообщений истории, выбранные фрагменты, до 600 путей и последние коммиты. На бесплатном тарифе Google может использовать данные для улучшения продуктов — см. [условия Gemini API](https://ai.google.dev/gemini-api/terms). Учитывай это при выборе приватного проекта.
- Обновления GitHub подтягиваются командой `/refresh`. Индекс выборочный; для большего покрытия можно увеличить `MAX_FILES`.
- При ошибке Gemini, пустом ответе или превышении квоты бот переходит к локальному поиску. После HTTP 429 действует пауза перед следующим обращением к Gemini.
- Для Gemini 3 и 4 выбран уровень размышлений `LOW`, лимит ответа — 4096 токенов; время ожидания регулируется `GEMINI_TIMEOUT_SECONDS`.
- Код и README не исполняются. Инструментов записи на GitHub, shell-команд и создания коммитов у бота нет.
- Telegram-сообщения обрабатываются последовательно. Во время индексации и ответа модели следующие сообщения ждут. После аварии между отправкой ответа и сохранением offset возможен повтор ответа.
- Если GitHub возвращает обрезанное дерево, бот сообщает об этом. Подмодули и символические ссылки не индексируются.
- Бот проверяет webhook и не удаляет его автоматически. Telegram 409 означает конфликт с другим экземпляром.
